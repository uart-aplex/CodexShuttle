# Preview.13: Preserve Active Browser Cache During Restore

## Problem

The executable-in-target guard treated a surviving Chrome extension host as a reason to block the entire restore before copying. Closing the Codex window does not necessarily terminate that independent background process. Simply ignoring it would leave Robocopy attempting to replace an executable in use.

## Change

For the exact bundled Chrome layout beneath the destination Codex home, `plugins/cache/openai-bundled/chrome/<version>/extension-host/windows/{x64,arm64}/extension-host.exe`, a running host causes the Chrome cache subtree to be retained locally. The plan is checked before preflight and again after package verification. Dry Run uses the same preservation policy.

Directory exclusions apply to copy, mirror deletion, preflight comparison and profile-path remapping. If a source ancestor is absent, the highest missing source subtree is retained as well: Robocopy can otherwise purge the ancestor recursively without honoring the deeper exclusion. The log lists the actual preserved paths. This may retain additional destination-only cache files, but never omits incoming files in the missing ancestor.

Conversation history and automatic path repair still run. The final success message explicitly states that the active Chrome cache was kept locally, not restored. This is not an exact replacement of that cache. Close the extension host before a later restore if the incoming Chrome cache is required. An inactive host gets no special exclusion.

The exception does not recognize arbitrary executables by filename alone. Other plugins, main Codex processes and Shuttle executables in selected replacement folders remain protected by the existing checks. The UI still requires Codex to close. No browser or background process is killed automatically. A new executable starting during file transfer can still cause a copy failure; locked files are never force-overwritten.

## Validation

On 2026-11-07, 163 core and 10 WPF tests passed; five opt-in native/real-package tests were skipped in this standard run. The focused restore regression group passed all 20 cases.

Regression tests exercise FullProfile and HistoryAndTools with a locked synthetic extension executable, both with and without Chrome files in the package. They verify preserved binary/config bytes, no path remapping of retained config, no installation of incoming Chrome-only files, successful restoration of other plugins and conversation paths, and unchanged package checksums. Additional cases cover an inactive Chrome host, unknown executable names/layouts, sibling directory boundaries and retained generic process blocking.

Tests use isolated temporary data and simulated process inventories. No production restore, process termination or USB modification is performed during development.
