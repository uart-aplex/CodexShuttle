# Preview.9: Conversation Conflict Classification

## Root Cause

Preview.8 required both the physical rollout hash and every projected-history field to match. Previously restored conversations can contain the destination user's profile paths instead of the source paths. Codex can also append `thread_settings_applied` records or rebuild projection offsets without adding messages. Compression and JSON serialization differences similarly change physical bytes. Calling all of these differences conflicts overstated the result.

Read-only inspection of eight older, physically different rollout pairs found matching records after profile-path normalization and exclusion of appended settings-only events. No conversation text was exported into this repository, and no production database or rollout was modified. This sample is not proof that every reported conflict is metadata-only.

## Comparison Rules

- **Identical**: exact rollout and projected-history fingerprints match.
- **Equivalent**: both normalized rollout records and normalized projected content match. Local data is left untouched, even if the item is selected.
- **Conflict**: differences remain in rollout records and/or projected turns/items. The local conversation remains unchanged; selected incoming revisions are retained separately under the existing conflict policy.

Comparison decompresses rollouts as streams, parses JSON, sorts object keys and preserves array/record order. It normalizes only recorded source/current user roots and explicitly approved workspace mappings, with directory boundaries and one-pass replacement. It ignores the known settings-only event `event_msg/thread_settings_applied`; unknown event types are not discarded.

Projected-content comparison excludes byte positions, rollout ordinal values and the projection cursor table. Row ordering still follows rollout ordinals. Turn/item IDs, status, timestamps, error data, message/tool contents and realtime items remain compared. JSON-valued columns are parsed; arbitrary text remains text. Profile path substitutions are comparison-only, including paths embedded in historical text, and are not written back.

This does not merge two divergent timelines, import a newer same-ID version over local history, or infer sameness from conversation age. A different projection with an equal rollout still produces an explicit conflict reason. Missing/invalid local index paths remain blocked.

## Safety And Verification

Physical package checksums, source verification, approved-plan fingerprints and rollback guards are unchanged. Normalized hashes are never used to authorize deletion or overwrite. A selected Equivalent entry creates no change and no restore point. Stream comparison is cancellable and bounded to 32 MiB characters per record and 2 GiB characters per rollout; exceeding a bound stops the operation rather than assuming equality.

Validation on 2026-11-07: 123 core tests and 8 Windows UI tests passed, with four opt-in tests skipped in the standard run. New tests cover migration paths, compressed/plain equivalence, settings-only tails, projection offsets, zero-write behavior, usernames with common prefixes, escaped paths, JSON ordering and real added user/assistant/tool/unknown-event content. Existing projected-message conflict and rollback coverage remains in place. The eight sampled production rollout pairs also match under the new rollout comparison; full live-profile classification requires closing Codex and running Dry Run again.

Use preview.9 against the existing verified backup; no new backup is required for this classification fix. Close Codex first. The UI places the reason beside the action, with tooltips for full titles/reasons. Desktop GUI end-to-end acceptance remains pending.
