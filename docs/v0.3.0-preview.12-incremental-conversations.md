# Preview.12: Verified Conversation Continuations

## Why The Previous Merge Was Incomplete

Previous previews imported missing thread IDs but treated every meaningful same-ID difference as a conflict. An incoming conversation with additional turns was saved outside Codex instead of becoming a continuation of the existing chat. This protected local data but did not support continuing work across computers.

## Decisions

- `Add`: a missing conversation, subject to existing metadata and workspace checks.
- `Update`: the incoming rollout is a strict extension of the local rollout, and every compared projection table is either equal or a source-side extension. Apply activates the incoming continuation under the same thread ID.
- `LocalAhead`: the local rollout is a strict extension, and every projection table is equal or a local-side extension. Keep local without writing or creating another restore point.
- `Identical` / `Equivalent`: keep local without writing.
- `Conflict`: divergent records, changed earlier turns/items, differing table directions or projection/rollout disagreement. Preserve the selected incoming revision outside Codex; do not replace local history or invent an ordering for two branches.

Only the validated paginated layout supports Update. Legacy same-ID differences remain conflicts. Comparison is ordered, checks all message/tool records, normalizes only previously supported migration differences, and validates the entire longer rollout. It does not infer ancestry from timestamps, file length or message counts. Unknown schemas remain blocked.

## Applying And Recovering

Incoming rollout bytes are written without replacement under `sessions/shuttle-revisions/<revision-key>/<original-name>`. Compression and projection byte offsets stay together. The original local rollout remains intact; the primary row points at the new revision. This copies the selected incoming conversation file as a unit, not just a byte suffix, and does not recopy the entire profile or workspace.

The primary update preserves local title, project/parent relationships, pins, archive state, working directory and provider metadata. Only the rollout reference and supported recency/token counters are advanced. The validated incoming projection replaces the selected thread's projection transactionally, not other chats. Existing account/tool settings remain outside Merge Restore.

The local metadata restore point records updated IDs as well as added IDs. Rollback restores updated rows and projections from verified snapshots, independently handling either side of an attached-database partial commit. It deletes only newly owned revisions. Both original and imported file hashes and before/after database fingerprints are checked; later local changes block rollback rather than being discarded. Original rollout revisions are retained for recovery and consume disk space; they are not automatically deleted. No workspace snapshot is made.

Existing completed backups remain usable; no package-format change or mandatory new backup is needed. Backups created after an update include the active revision and can migrate it to another computer. Repeating the same merge is a no-op for the updated chat.

## Operation

1. Close Codex Desktop, CLI and IDE sessions before importing.
2. Open Merge Restore and select the completed USB backup at its current drive letter.
3. Run Dry Run. Review Update, Add, LocalAhead, Conflict and Blocked rows.
4. Use Select New + Updates, or choose individual entries. Review workspace additions separately.
5. Import Selected. Read the final counts for new conversations and updated conversations.

Do not use Disaster Recovery to resolve a merge conflict. Existing workspace files still remain local, even if the backup contains newer file contents. Review project file changes separately before continuing development. Genuine two-sided conversation branches, arbitrary message splicing, active-profile tool merging and automatic synchronization remain unsupported.

## Validation

The standard suite passed 151 core and 10 WPF tests on 2026-11-07, with five opt-in cases skipped. New tests cover plain/compressed continuations, different user roots, original-byte preservation, local title/provider/project/pin preservation, unrelated chats, idempotence, four injected failure checkpoints, both partial database commit directions, local-ahead no-ops, divergent branches, projection disagreement, stale approval, newer-work rollback guards, malformed tails, and onward migration to a third synthetic profile.

An opt-in installed Codex app-server test imported a synthetic base chat, merged a compressed continuation into that same ID, read both old and new turns, verified an unrelated local chat, and resumed the updated chat without a model request. No production merge or restore was performed. General Desktop GUI acceptance remains pending. Sixteen offscreen WPF renders passed at four viewport sizes, including the revised selection button.

A read-only diagnostic of the reported conversation found both rollout and projected-history source extensions relative to the retained pre-merge state. Production conversation content and diagnostics are not included in this repository.
