# v0.3 Safe Merge Design

Status: Phase 1 preview implemented for a restricted legacy JSONL / primary SQLite layout. Automated and isolated app-server checks passed; Desktop GUI acceptance remains pending. Automatic sync is disabled. See [test results](v0.3-test-results.md).

## Safety boundary

Merge Restore is a separate service, never a switch passed to the mirror planner. The existing disaster-recovery restore remains available under an explicit disaster-recovery label. Its `RestorePlanner`, `FileMirrorService` (`/MIR`), whole-profile database replacement and broad path rewriting are not reusable merge operations.

Phase 1 imports explicitly selected conversations only. It never copies workspace files, credentials, configuration, skills, plugins, project registries or provider settings. Local-only data cannot be deleted by an absent source entry. Same-ID different-content histories are preserved outside the active Codex profile as immutable conflict objects; no JSONL concatenation or hand-made thread-ID forks. Even a source extension of a local conversation is held for review rather than overwriting local history.

## API research (2026-10-10)

- Official documentation: https://learn.chatgpt.com/docs/app-server (also reached through https://developers.openai.com/codex/app-server/).
- Documented `thread/read`, `thread/resume`, and `thread/fork` operate on stored threads. The reviewed documentation does not establish an atomic cross-profile import/merge endpoint.
- Locally generated protocol schemas from `codex-cli 0.162.0-alpha.2` confirm the public resume parameters have `threadId` and `cwd`, but no `path` or `history` import parameter. These schemas are generated into ignored artifacts, not copied into public source.
- Consequently use a conservative, offline SQLite adapter for the supported primary `state_5.sqlite` threads table. Only parameterized INSERT of absent IDs is allowed. No REPLACE/upsert, no copying an active database. Unknown required columns, unrecognized triggers and incompatible metadata fail closed. A separate app-server compatibility test verifies imported synthetic history using the installed server without sending model turns.
- Desktop GUI opening/resumption still requires an isolated Desktop acceptance run; backend RPC success alone does not certify the Desktop UI. No production-profile experiment is authorized by this task.

## Reference project

Reviewed https://github.com/tang12306/codex-sync at commit `464aeb27ca1320bf1afac9b89ad4888267e6ba56` (MIT). Its `codex_sync/backup_import.py` uses timestamp comparisons, rewrites rollout metadata for new IDs and inserts using `INSERT OR REPLACE`. The backup-before-import and selective-import concepts are useful, but its conflict policy is not adopted: timestamps do not establish ancestry, and a replacement statement is inappropriate for the non-overwrite invariant. No reference implementation code is copied or executed.

## Phase 1 architecture

1. Validate the existing schema-2 package and checksums; reject traversal/reparse paths and unlisted sessions. Inventory active and archived JSONL via `session_meta.id`, parse every record, hash contents, cross-check SQLite IDs. Titles and filenames are not identity.
2. Produce a deterministic preview bound to source hashes, destination history/index/metadata and path mappings. Source/target change after preview requires a new preview. All selections default to excluded.
3. Rebase only structured `cwd` fields in imported copies using explicit workspace mappings and the recorded source user-profile root. Never rewrite local transcripts or historical message text. Expose unmapped/missing working directories as blockers.
4. Require Codex stopped, acquire package/profile locks, revalidate, and create a verified local restore point outside the USB package and Codex profile. Use SQLite's backup API, not raw active SQLite copying. Preserve the exact original session index and a durable write-ahead operation journal.
5. Add new session files without overwrite and insert supported metadata in one SQLite transaction. Append only new index entries, retaining existing bytes. Existing project associations remain untouched; imported project associations are deferred to Phase 2.
6. Use the journal for compensation and crash recovery. Undo only files/rows introduced by this operation and restore the index only when its current contents match the expected operation result. If subsequent local edits exist, refuse rollback rather than erase them. Retain verified restore points for inspection.
7. Repeated imports compare mapped content and retained conflicts, producing no new changes when already present. Corruption, duplicate IDs, stale previews and incompatible databases block mutation.

## Compatibility constraints

- Supported: self-contained legacy JSONL sessions plus primary `state_5.sqlite`. The installed server-generated schema was tested, including exact known timestamp/recency triggers. Unknown trigger SQL is rejected rather than trusting names. Non-null foreign keys are rejected except supported optional project/sidebar relationships explicitly cleared on new rows.
- Nested `sqlite/state_*.sqlite`, multiple database generations and non-legacy history modes are blocked. Do not delete or rename indexes to bypass this check. External SQLite locations configured outside the selected profile are not validated or certified for merge.
- Source providers are retained in incoming thread metadata; destination provider configuration is never changed. Provider-specific Desktop filters may hide imported conversations. No inference or provider switch is performed by the compatibility test.
- Imported project/sidebar associations are not mapped in Phase 1. Selection provides per-import inclusion, not persistent Local Only/project sync policy.
- Account names, forward slashes and extended Windows path prefixes are handled for structured cwd and generated rollout paths. Historical message text, referenced external files and arbitrary embedded paths are not rewritten. Keep original E: workspace paths where practical.
- Local restore points contain a SQLite backup and original index, not another full workspace/transcript copy: original transcripts/workspaces are never modified. Rollback removes only verified additions; it does not replace the whole database over newer work.
- File operations and SQLite are not one native atomic transaction. A durable journal supports compensating recovery. Physical power loss, disk-full and hardware failure guarantees need dedicated testing. Do not run another writer during import/recovery.
- Conflict source identity uses the legacy package computer name plus content hash, not a globally unique device identity or proven ancestry. UUID registration and leases are not claimed in this preview.
- Restore points, conflicts and logs under `%LOCALAPPDATA%\CodexShuttle` are private plaintext data with normal user-profile OS permissions. Do not place them in a shared/cloud folder. Encryption is not implemented.
- Complete inventory, package checksum verification and logical database fingerprinting favor safety over speed. Sessions above 256 MiB are rejected; large-history performance needs profiling.

## Manual preview workflow

1. Select a completed package in **Merge Restore**, then **Dry Run** to inventory both sides.
2. Select individual sessions and add workspace mappings when needed. Edits invalidate the plan; run **Dry Run** again.
3. Review actions/paths, close Codex Desktop/CLI/IDE, acknowledge the preview warning and confirm **Import Selected**. Settings, tools, credentials and workspace files are excluded.
4. **Conflict Review** shows conflicts in the current preview. Run Dry Run after importing to refresh retained status. This is not yet a global conflict browser or fork tool.
5. **Restore Point Manager** lists local restore points and offers guarded rollback with confirmation. Interrupted `Applying` points block further import into that profile until recovered.

## Later phases (not enabled)

- Phase 2: stable project UUID registry with explicit Local Only, Conversations Only, Conversations + Workspace and Backup Only policies. Per-device path mapping; workspace import is additive and conflict-aware, never mirror deletion.
- Phase 3: `IObjectStore` local-folder transport first, compatible with USB/OneDrive/Drive folders. Immutable objects, content hashes and manifests published by rename; no live SQLite in transport. WebDAV and authenticated encryption (AEAD with explicit portable key recovery) require separate implementation/security tests. No plaintext cloud upload until encryption is implemented.
- Phase 4: device UUID, thread UUID, content revision and parent revision hashes; ancestry rather than timestamp precedence. Official fork API integration after compatibility verification. Shared-session continuation remains disabled until explicit leases/ownership and expiry are implemented.
- Phase 5: WPF Merge Restore, Conflict Review and Restore Point Manager first. Sync Now and Sync Settings must not imply implemented automatic/cloud synchronization.

## Release gates

Automated safety tests plus isolated app-server tests are required. Production merge remains an explicit preview feature pending isolated Desktop GUI acceptance. No scheduler, cloud upload or automatic sync is enabled by this implementation. Operation logs, snapshots and conflict contents are private local data, excluded from Git.
