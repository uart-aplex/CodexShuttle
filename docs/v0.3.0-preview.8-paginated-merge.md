# Preview.8: Paginated Merge Restore

## Cause

The earlier merge adapter accepted only self-contained legacy JSONL histories. Profiles with a nested index were blocked before inventory, even when Codex had already reconciled that index into the primary database. Newer paginated histories also require `thread_history_1.sqlite`: copying only rollout files and primary thread rows is insufficient.

The UI had a second issue: changing conversation checkboxes invalidated the entire preview. A general refresh could also replace a terminal error with a selection/path-change message.

## Supported Operation

- Selectively insert missing thread IDs into primary `state_5.sqlite` and all four known paginated history tables.
- Keep compressed or plain rollout bytes unchanged so projection byte offsets remain valid. The primary index uses the logical `.jsonl` path and Codex resolves its compressed representation.
- Map the imported index's rollout path and structured working directory to the destination profile/workspace. Arbitrary historical message text and rollout bytes are not rewritten. Fixed workspace paths must exist, or be explicitly mapped.
- Preserve unrelated local conversations, workspaces, settings, credentials, skills and plugins. Merge does not transfer those workspaces or tools; Backup/Disaster Recovery are separate operations with different semantics.
- Compare both rollout content and projected history. Same-ID divergent content is retained outside the active profile with its projected history export. It is not appended to, substituted for, or opened as a second local chat.
- Allow already-reconciled nested indexes only with an existing Codex reconciliation marker and primary database. Never fabricate the marker or delete the nested index.

After Dry Run, checkbox selection enables Import Selected once the preview warning is accepted. Changing paths invalidates the preview; Apply rechecks the package, destination and mappings. Failures remain visible, with the full log path recorded.

## Safety Boundaries

Close all Codex clients before Dry Run/import. Inspection uses private database/WAL copies and refuses inconsistent or locked inputs. Source checksums remain mandatory. Unknown tables, columns, keys, triggers, primary database generations and mixed source history modes are blocked. Destination orphan rollout IDs block duplicate imports. No production-profile import was performed during development.

Merge creates a local metadata restore point outside both package and profile. It includes the primary and history databases plus the session index, not full workspace copies and not USB pre-restore duplication. Insert-only changes are journaled. Recovery checks both database states independently, including partial attached-database WAL commits; later local changes prevent automatic rollback from removing newer work. Schema/migration changes also invalidate the history fingerprint.

Do not use Disaster Recovery to bypass a merge block. Do not disable checksums or delete a database. Keep independently verified backups before using this preview.

## Validation

On 2026-11-07:

- Standard suite: 115 core tests and 8 Windows UI tests passed; 4 environment-dependent tests skipped in that run.
- Opt-in native paginated test passed against installed app-server `0.167.0-alpha.3.2`: imported compressed synthetic history can be read and resumed with the destination user's mapped working directory, while an unrelated personal thread remains readable. Projected turns were synthetic data inserted into native-created schemas; no model request was made.
- Opt-in read-only package preview passed against an isolated destination. It recognized 120 indexed conversations: 104 additions and 16 blocked because their working directories did not exist on the current machine. This is not a merge assessment against the live local profile.
- Regression coverage includes byte/offset preservation, unchanged package files, idempotence, divergent projected history, unknown schema rejection, orphan IDs, rollback at four checkpoints, partial database commits and preservation of newer local history.
- Sixteen offscreen WPF layout renders passed at 760x440, 800x560, 1024x680 and 1366x720. View-model tests verify selection enables import and refresh preserves failures.

Desktop GUI end-to-end acceptance with imported chats remains pending. This is a preview, not universal schema compatibility or automatic two-way message synchronization.
