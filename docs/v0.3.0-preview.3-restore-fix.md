# v0.3.0-preview.3 Restore Compatibility Fix

Date: 2026-10-16. Scope: Windows WPF / .NET 8; manual Disaster Recovery compatibility and fail-closed Merge Restore validation. Automatic synchronization remains disabled/unimplemented.

This release includes the separately published preview.2 log auto-scroll crash fix (commit `0a08455`) and its WPF regression tests. Preview.3 distinguishes the combined build from that earlier version; the existing preview.2 tag is not replaced.

## Root Cause

A reported replacement restore stopped at preflight because its SQLite index referenced a logical `.jsonl` rollout while the package contained the corresponding `.jsonl.zst` file. The old resolver inventoried only plain JSONL, incorrectly treating the conversation as missing. This failure happened before copying, not after a successful restore.

Current Codex supports a logical plain path backed by a compressed sibling and prefers the plain file when both exist. The implementation was checked against [official rollout compression source](https://github.com/openai/codex/blob/6ae8b8aa7c608730d4315d59c5c081897ae02780/codex-rs/rollout/src/compression.rs) and exercised with the installed native app-server. No external project implementation was copied.

A second compatibility gap affected `HistoryAndTools`: `thread_history_1.sqlite` and its WAL/SHM family were not included. Newer paginated histories can depend on this database in addition to rollout files and the state index.

## Changes

- Inventory plain and compressed rollout files. Resolve indexes to logical destination `.jsonl` paths while verifying the physical `.jsonl.zst` file when needed.
- Treat plain/compressed siblings as one logical rollout; reject genuinely ambiguous filename fallbacks across different directories.
- Preserve compressed bytes without decompressing, recompressing or concatenating transcripts.
- Include `thread_history_1.sqlite`, `-wal` and `-shm` in the HistoryAndTools migration policy. Credentials and provider configuration remain excluded from that mode.
- Run SQLite quick-check on an available history database; reject a missing history database when indexed non-legacy histories require it. Validation occurs before destination overwrite.
- Explicitly block compressed-only Merge Restore input instead of silently skipping conversations. This is a safety guard, not compressed/paginated merge support.
- Add the informational version, explicit Disaster Recovery mode and replacement warning to restore logs.

Existing account-root remapping and post-copy index repair remain in place. Compressed message contents are not rewritten; arbitrary old profile links embedded inside compressed transcript text are not covered by this fix. Shared workspaces should retain their intended stable paths.

## Verification

All **90 automated test cases passed, 0 failed, 0 skipped** (84 core/integration and 6 WPF log-scroll cases) on Windows using .NET SDK 8.0.422. The native acceptance test used `codex-cli 0.163.0-alpha.10.2` with isolated temporary source and destination profiles, not the production profile.

Coverage added in this revision:

- Logical plain and compressed index paths, archived fallback and ambiguity rejection.
- Plain/compressed sibling preference and byte-preserving restore.
- Committed WAL data restored with the paginated history database.
- Missing/corrupt required history database rejected before destination state changes.
- HistoryAndTools inclusion rules and compressed-only Merge Restore rejection.
- Native `rollout/compress` on a synthetic legacy transcript, followed by actual Shuttle restore and app-server `thread/read` and `thread/resume` on the restored compressed conversation. No model turn or provider request was made.

The WAL test stages a quiescent synthetic database and committed WAL into a fixture. It does not establish that copying live production databases is safe. Close Codex before backup or replacement restore; Merge Restore does not copy active SQLite databases to merge them.

A read-only path diagnostic on the reported USB package verified **142 conversation file paths** with **0 repairs**. It reported **10 unavailable entries in an already-reconciled legacy index** as warnings; active indexes passed the path check. This diagnostic was not a full package checksum verification, a production restore, or proof that every historical conversation opens in Desktop.

## Limits and Recovery

Disaster Recovery still replaces selected local state and can overwrite/delete destination-only conversations and workspace files. This fix must not be presented as a solution for combining two independent histories. Merge Restore remains limited to supported self-contained legacy JSONL profiles; compressed-only, paginated and unsupported index layouts fail closed.

The native read/resume acceptance test covers a synthetic compressed legacy conversation. End-to-end Desktop GUI acceptance and native paginated conversation recovery are not yet verified. Required database presence and integrity checks cannot guarantee compatibility with every future Codex schema.

Protect local-only work independently before replacement. Pushing this repository protects committed source and documentation, not chats or ignored executables. See [recovery after workspace replacement](restore-safety-and-handoff.md#recover-the-fixes-after-workspace-replacement). Do not upload recovery snapshots, raw operation logs, conversation data or credentials to this public repository.
