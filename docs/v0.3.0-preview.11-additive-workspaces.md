# Preview.11: Additive Workspace Merge

## Behavior

Merge Restore now defaults to adding missing files from every enabled workspace in the selected backup manifest. The workspace list and counts are shown separately from selected conversations. Existing files, including files with different source contents, remain untouched. Local-only files are not removed. This is additive transfer, not mirror restore, file-content reconciliation or automatic two-way synchronization.

A missing conversation working directory is no longer a blocker when the enabled package workspace supplies that exact directory. The backed-up directory contents are transferred before new thread rows are inserted. Missing data outside the backup cannot be invented; those conversations remain blocked. Source profile roots map to the destination user. Fixed workspace paths remain unchanged unless a whole-workspace mapping is explicitly supplied. USB source paths always resolve beneath the currently selected package, never the source computer's recorded USB mount.

Use Dry Run, inspect the workspace additions, choose Select New or individual conversation checkboxes, and review Import Selected. An operation with no conversations selected can still add workspace files; its confirmation and result report that separately. Disable Add missing workspace files for conversation-only operation.

## Copy And Recovery Guarantees

- No mirror operation, destination deletion, existing-file overwrite or full workspace snapshot is used.
- Preview computes SHA-256 for missing source files only. Existing destination files are retained without hashing/comparing their contents. The package's historical checksum list still covers its original scope; new workspace hashes verify transfer from the previewed source, not the original backup-creation contents.
- Apply checks the source tree and missing destinations again. For unchanged source length/timestamp/path it may reuse the approved content hash, avoiding another full USB read before copying. Every copied temporary file is re-read and checked against that approved hash before a no-overwrite rename.
- Interrupted writes do not publish partial final files. Cancellation/failure cleans the current process's temporary file. A forced process kill can leave a uniquely named temporary sibling; it is not treated as a completed destination file and is listed in the local workspace receipt. No broad cleanup of unknown files is performed.
- Completed workspace additions remain on cancellation, failure or conversation rollback. They are deliberately not included in the deletion-based conversation journal. Retry scans again and only fills remaining gaps, preserving subsequent user edits.
- Workspace receipts live under `%LOCALAPPDATA%\CodexShuttle\merge\workspace-runs`. They contain paths and hashes, not file contents, and must not be committed or uploaded without review.
- Profile metadata is rechecked after workspace copying. Conversation restore points and rollback still cover metadata and imported conversation revisions only. A failed conversation import is not reported as a successful overall merge.

## Guards And Limits

Missing drives, insufficient free space, FAT32 size limits, package/target overlap, profile/store/system targets, unsafe package paths, links, overlapping workspace roots and file/directory collisions are rejected. Source files are read without sharing write access. Credential filename/directory exclusions reuse the existing migration policy. Existing Windows file attributes/ACLs are not imported; file contents and last-write timestamps are copied.

Subfolder mappings inside a larger backed-up workspace are intentionally rejected for workspace copying; use whole-root mappings or turn workspace copying off. Same-ID conversation message append/ancestry merge, existing-file conflict resolution, active-profile tool/settings merge and general Desktop GUI acceptance remain outside this change.

## Validation

On 2026-11-07, the standard suite passed 136 core and 10 WPF tests, with four opt-in cases skipped in that run. Workspace regressions cover absent project + paginated chat, cross-user paths, existing local modifications, local-only files, read-only Git pack files, empty source directories, credential exclusion, cancellation/retry, chat rollback retaining project files, changed source/destination, same-length/same-time content changes, disabled/absent package data, collisions, protected roots and relocated USB packages.

An opt-in isolated native Codex app-server test passed: a missing mapped workspace was supplied from a synthetic package, the imported compressed paginated chat was readable/resumable in that workspace, and the unrelated personal chat remained readable. No model call or production import was made.

A read-only scan of an actual missing project found 9,267 missing files, 2,113 directories and 2,103,692,536 bytes. The planner confirmed it could supply the working directory; the destination remained absent after the scan. Production conversations and project files were not modified during validation.
