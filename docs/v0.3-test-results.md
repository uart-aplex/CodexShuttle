## Reproduction

Use .NET 8 SDK and an explicitly selected installed Codex executable:

```powershell
dotnet build CodexShuttle.sln -c Release
$env:CODEXSHUTTLE_TEST_CODEX = 'C:\path\to\codex.exe'
dotnet test CodexShuttle.sln -c Release
powershell.exe -NoProfile -STA -File scripts\Test-Layout.ps1
```

Without the environment variable, the app-server test is inconclusive/skipped, not silently successful. Tests create disposable GUID-scoped temporary fixtures. The child receives isolated CODEX_HOME, CODEX_SQLITE_HOME, HOME, USERPROFILE, APPDATA and LOCALAPPDATA; inherited API-key/token variables are removed. Only the owned test process is stopped during cleanup.

## Remaining Acceptance

- Explicitly isolated Desktop GUI: verify sidebar display/open/continuation with approved test credentials. Production-profile testing was not authorized or performed.
- Reviewed adapters for nested/external databases, newer history modes and future schemas.
- Actual process termination at each journal boundary, physical power loss, full disks, read-only media and very large histories. Exception injection/journal-state simulation is not physical power-loss testing.
- Interactive WPF command testing: render checks validate layout, not every interaction.
- Later phases: stable device/project IDs, Local Only/project policies, immutable cloud transport, encryption, ancestry-aware forks and ownership leases. None is enabled or claimed complete.
